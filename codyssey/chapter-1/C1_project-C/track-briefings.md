# Project C — 4개 트랙 예습 브리핑 (전 트랙 대비용)

> 랜덤 팀에서 어느 역할이 걸려도 바로 리딩할 수 있도록, 4개 트랙을 각각 예습한다.
> 각 트랙: **목표 → 이것만 알면 됨 → 실습 스텝 → 자주 막히는 지점 → 회의 리딩 한마디**.
> 도구: Make(자동화) + OpenAI(텍스트·이미지) + Notion(저장). 관련 설계도: `workflow/workflow-spec.md`, `prompts/prompt-templates.md`.

---

# 🔧 트랙 A — 워크플로우 아키텍트 (Make 빌드)

### 목표
주제 입력 → 텍스트 3종 + 이미지 → 노션 저장이 **자동으로 한 번에** 돌아가는 Make 시나리오를 만든다. (산출물 ①)

### 이것만 알면 됨 (핵심 개념 3개)
1. **모듈(Module)** = 하나의 동작 블록. 서로 선으로 이으면 왼쪽 출력이 오른쪽 입력으로 흐른다.
2. **트리거(Trigger)** = 시나리오의 첫 모듈. "무슨 일이 생기면 시작할지"(폼 응답 도착 등)를 정한다.
3. **매핑(Mapping)** = 이전 모듈의 결과값(파란 태그)을 다음 모듈 입력칸에 끼워 넣는 것. 이게 자동화의 핵심이다.

### 실습 스텝 (클릭 순서)
1. Make → **Create a new scenario**.
2. 첫 모듈: **Google Forms › Watch Responses** (또는 Webhooks › Custom webhook) → 폼 연결.
3. **OpenAI › Create a Chat Completion** 모듈 3개 추가 — 각각 인스타/블로그/X 프롬프트 입력. `{{topic}}` 자리에 1번 모듈의 폼 응답값을 **매핑**.
4. **OpenAI › Create an Image** 모듈 추가 — 주제 기반 이미지 프롬프트.
5. **Notion › Create a Database Item** — 플랫폼 속성에 인스타/블로그/X, 본문에 3~5번 결과 매핑, 이미지 첨부. (플랫폼별 구분 저장이 요구사항이라 항목 3개로 나눔)
6. 우하단 **Run once** → 폼 제출 → 초록불 확인.
7. 스크린샷: 전체 구조 / 각 모듈 설정 / 실행 성공 / 노션 결과 (`workflow-spec.md`의 캡처 목록 참고).

### 자주 막히는 지점
- **OpenAI 커넥션 없음** → API 키를 먼저 연결해야 모듈이 작동. (팀에 키 있는지 [0]단계에서 확인)
- **매핑 태그가 안 뜸** → 이전 모듈을 한 번 실행(Run)해야 출력 필드가 생겨 매핑 가능.
- **노션 저장 실패** → DB 속성 이름/타입이 D가 만든 스키마와 정확히 일치해야 함.

### 회의 리딩 한마디
> "노션 DB 스키마부터 확정하면 제가 저장 모듈까지 한 번에 연결할게요. 프롬프트랑 이미지 프롬프트만 주세요."

# ✍️ 트랙 B — 프롬프트 엔지니어

### 목표
한 주제를 플랫폼 특성에 맞게 변환하는 프롬프트를 설계하고, **수정 과정(초안→수정→최종)**을 기록한다. (산출물 ③)

### 이것만 알면 됨 (설계 3원칙)
플랫폼마다 아래 3가지를 **숫자·구조로 못 박아야** LLM이 흔들리지 않는다.
| 축 | 인스타 | 블로그 | X |
|----|--------|--------|---|
| 분량 | 2~4문장 | 500자↑ | 280자 이내 |
| 구조 | 캡션+해시태그 10개 | 제목+소제목 3개+문단 | 요약+해시태그 2~3개 |
| 톤 | 친근·이모지 | 정보·신뢰 | 임팩트·핵심 |
- **"짧게 써줘"(X) → "2~4문장, 100자 내외로"(O)**: 모호한 지시는 실패한다. 숫자로 지정.
- 금지 규칙도 명시("인스타에 소제목 금지").

### 실습 스텝
1. `prompts/prompt-templates.md`의 초안 v1을 그대로 시작점으로.
2. Make(또는 ChatGPT)에서 실제 실행 → 결과가 규칙(글자수·해시태그 개수·280자)을 지켰는지 확인.
3. **어긋난 부분마다 수정 이력을 기록**: (1)이전 프롬프트 (2)원인 추정 (3)수정 프롬프트 (4)수정 후 결과 (5)학습 포인트.
4. 보너스: 톤 한 줄만 바꿔 A(친근)/B(전문) 두 버전 생성.

### 자주 막히는 지점
- **X가 280자를 넘김** → LLM은 글자 수 상한을 자주 어긴다. "반드시 280자 이내, 초과 시 줄여서 다시" 명시 + 결과 검수.
- **블로그가 500자 미달** → "공백 포함 500자 이상"으로 명확히, 소제목 개수도 숫자로.
- **수정 이력을 지어내면 안 됨** → 반드시 실제 실행 결과(raw 로그)를 근거로 기록. (평가 핵심)

### 회의 리딩 한마디
> "프롬프트 초안은 제가 준비해 왔어요. 첫 실행 결과 보고 어디가 규칙을 어기는지 같이 보면서 v2로 고쳐요."

# 🎨 트랙 C — 콘텐츠·이미지 디렉터

### 목표
주제에 맞는 **SNS용 품질의 대표 이미지**를 만들고, 3개 플랫폼 텍스트가 규칙을 지켰는지 최종 검수한다. 보너스 A/B **효과 결론**을 정리한다. (산출물 ②)

### 이것만 알면 됨
- **이미지 프롬프트 = 주제 + 스타일 + 구도 + 용도**. 예: "홈카페 라떼아트, 밝은 자연광, 미니멀 감성, 정사각형 SNS 썸네일, 텍스트 없음".
- **SNS 품질 기준**: 흐릿하지 않게, 인스타는 정사각(1:1)/블로그는 가로가 유리, 저작권 자유(AI 생성물).
- **A/B 결론은 "느낌"이 아니라 근거로**: 어떤 톤이 어떤 플랫폼/주제에서 더 잘 맞았는지, 왜인지.

### 실습 스텝
1. 이미지 프롬프트 초안 작성 → OpenAI(DALL·E) 또는 다른 이미지 AI로 1장 생성.
2. 품질 검수: 해상도·구도·주제 부합·SNS 적합성. 아니면 프롬프트 수정 후 재생성(실패본도 보존 — 도구 비교 자료).
3. 텍스트 검수 체크리스트로 3개 플랫폼 결과 점검:
   - [ ] 인스타: 해시태그 10개 내외? 캡션 길이 적절?
   - [ ] 블로그: 500자 이상? 소제목 3개 이상?
   - [ ] X: 280자 이내?
4. 보너스: A/B 두 버전 나란히 놓고 표로 비교 → 결론 문장 3~4개.

### 자주 막히는 지점
- **이미지에 이상한 글자가 박힘** → 프롬프트에 "no text, no letters" 추가.
- **주제와 겉도는 이미지** → 프롬프트에 핵심 키워드·분위기를 구체화.
- **A/B 결론이 막연함** → "친근형은 인스타 저장률↑ 느낌, 전문형은 블로그 신뢰도↑" 처럼 플랫폼×톤 매트릭스로.

### 회의 리딩 한마디
> "이미지랑 최종 검수는 제가 맡을게요. 텍스트 규칙(글자수·해시태그) 체크리스트로 마지막에 다 걸러낼게요."

# 📋 트랙 D — 노션·문서 PM

### 목표
결과를 **플랫폼별로 구분**해 노션에 저장하고, **프로젝트 개요·팀 역할·개인 작업 요약**을 담은 페이지를 완성한다. (산출물 ②)

### 이것만 알면 됨
- **노션 DB(데이터베이스)** = 표. 각 행이 콘텐츠 1개, 열이 속성(플랫폼/본문/이미지 등).
- **"플랫폼별 구분 저장" = 플랫폼 속성(Select)**으로 인스타/블로그/X를 나누는 것. Make가 여기에 자동으로 행을 추가한다.
- **스키마를 먼저 확정해야** 트랙 A가 저장 모듈을 연결할 수 있다 → **가장 먼저 움직여야 하는 트랙.**

### 실습 스텝
1. 노션에 페이지 생성 → 상단에 **프로젝트 개요**(주제·목표·사용 도구).
2. **팀 구성원 역할표** + **개인별 작업 요약** 섹션(요구사항 필수).
3. **콘텐츠 DB** 생성 — 속성: 제목 / 플랫폼(Select) / 본문(Text) / 대표이미지(Files) / 주제 / 생성일.
4. 이 DB 정보를 트랙 A에 전달(속성 이름·타입 정확히).
5. 실행 후 자동 저장된 결과가 플랫폼별로 잘 들어갔는지 확인.

### 자주 막히는 지점
- **Make ↔ 노션 속성 불일치** → 이름/타입이 한 글자라도 다르면 저장 실패. A와 이름을 맞춰 확정.
- **개인 작업 요약 누락** → 평가 필수 항목. 각자 한 일을 2~3줄씩 반드시 받기.
- **권한** → Make의 노션 커넥션에 해당 DB 접근 권한 공유돼 있어야 함.

### 회의 리딩 한마디
> "제가 노션 스키마를 지금 바로 만들게요. 속성 이름 확정되면 아키텍트가 저장 모듈 연결하면 돼요. 각자 한 일은 마지막에 저한테 2~3줄씩 주세요."

## 📌 전 트랙 공통 (평가 대비)
어느 트랙이든 **과제 목표 3가지**는 스스로 설명할 수 있어야 한다(동료 평가):
1. 하나의 주제 → 플랫폼별 콘텐츠 자동 생성 워크플로우
2. 생성형 AI + 이미지 AI 연동으로 텍스트+이미지 자동화
3. 포맷(글자수·해시태그·톤)을 고려한 프롬프트 설계 원리
