# AI 코딩 도구 사용 과정 증빙 — 대화 발췌

이 미션은 **Claude Code**(Anthropic)를 AI 코딩 도구로 사용해 진행했습니다. 아래는 2026-08-22 세션에서 있었던 두 가지 대표 사례를 실제 대화 그대로 발췌한 것입니다. 두 사례 모두 "AI가 코드를 대신 작성해주지만, 오류가 발생하면 직접 원인을 파악하고 수정한다"는 과제 취지를 그대로 보여줍니다 — Claude는 코드를 직접 고치지 않고 **원인을 설명**했고, **실제 코드 수정·git 명령 실행·재확인은 전부 사용자가 직접** 했습니다.

## 사례 1 — `js/main.js` 중복 파일 버그: 진단 → 설명 → 사용자 수정 → 검증

**상황**: 이전 세션 코드 리뷰에서 `js/main.js`가 `js/routine.js`와 내용이 완전히 동일한 중복 파일로 남아있는 게 발견되었고, 이번 세션에서 실제로 고치는 과정입니다.

> **Claude**: 홈(index.html)과 AI 루틴 추천(routine.html)의 콘솔 에러 메시지가 서로 다른 이유가 무엇일까요? 배포된 사이트에서 직접 확인해 주실 수 있을까요?

> **사용자**: 홈페이지 정상적으로 작동되는데, 어떤 오류를 확인 하라는거야?

> **Claude**: 맞습니다, 그게 정상입니다 — 지금 홈페이지에서 나는 오류는 화면이 깨지거나 기능이 안 되는 종류가 아니라서 그냥 보기엔 "정상 작동"처럼 보입니다. [...] F12 → Console 탭 → 새로고침하면 빨간색 에러 메시지가 나타날 것입니다.

> **사용자**(routine.html 콘솔): `Uncaught SyntaxError: Identifier 'form' has already been declared (at routine.js:1:1)`
> **사용자**(index.html 콘솔): `main.js:7 Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')`

> **Claude**: 두 에러가 정확히 예상대로 나왔습니다. 원인을 정리하면 — `index.html`은 `main.js`만 불러오는데 [...] `null`에 `.addEventListener`를 호출하려 하니 에러가 납니다. `routine.html`은 `main.js`와 `routine.js`를 둘 다 불러오는데, 두 파일이 똑같이 `const form = ...`을 선언해 문법 오류가 납니다. [...] **직접 수정해 주세요**: `js/main.js` 파일을 열고, 전체 내용을 지운 뒤 공유 코드 자리로 비워주세요.

> **사용자**: 수정했어

Claude는 파일을 다시 읽어(`Read`) 실제로 비워졌는지 확인만 하고, git 명령은 다시 사용자에게 안내했습니다.

> **Claude**: `git add js/main.js` / `git commit -m "..."` / `git push` — 각 명령어 설명 후 사용자가 직접 실행하도록 안내

> **사용자**: git add js/main.js 명령어가 안 먹어
> **Claude**: 어떤 에러 메시지가 나오나요? [...] (사용자 스스로 원인을 찾도록 즉시 정답을 주지 않고 되물음)
> **사용자**: 아냐 잘 됐어 푸시 했어
> **Claude**: 잘 됐습니다. Vercel 배포가 "Ready" 상태인지 확인하시고, 완료되면 배포 사이트에서 홈과 AI 루틴 추천 페이지 콘솔을 다시 확인해서 에러가 사라졌는지 알려주시겠어요?
> **사용자**: 어 사라졌어

## 사례 2 — 반응형 스크린샷 재촬영 요청: 산출물 검증 → 문제 발견 → 재작업 요청

**상황**: 사용자가 반응형 증빙 스크린샷 3장을 업로드했고, Claude가 완료 처리 전에 실제 파일을 열어 내용을 검증한 사례입니다.

> **사용자**: C2_mission-03 에 screenshots 폴더내에 업로드 했어 확인해줘
> **Claude**: 업로드 확인했습니다 — 3장 다 열어봤는데, 2장(데스크톱/모바일)에 문제가 있어서 재촬영을 요청드립니다. [...] 주소창을 보니 배포 URL이 아니라 로컬 파일(`file:///.../routine-friend/index.html`)을 열어서 찍으신 것 같습니다. [...] 모바일 화면은 개발자도구 콘솔 창까지 화면 절반을 차지한 채로 찍혀서 빨간 에러 메시지가 그대로 보입니다.

사용자가 배포 URL 기준으로 재촬영해 다시 올렸고, Claude가 다시 실제 이미지를 열어 확인했습니다.

> **Claude**: 확인했습니다 — 이번엔 배포 URL(`routine-friendtest.vercel.app`)에서 찍혔고, 모바일 쪽도 에러 없이 깨끗합니다. 좋습니다.

이 과정에서 발견한 "로컬 파일과 배포 URL의 차이"는 `QnA.md` Q7로 별도 정리해 과제 목표 ⑤(로컬 환경과 배포 환경의 차이) 근거로도 재사용했습니다.

## 이 두 사례가 보여주는 작업 방식

| 단계 | Claude의 역할 | 사용자의 역할 |
|---|---|---|
| 진단 | 콘솔 에러/스크린샷 등 증거를 직접 확인·요청 | 실제 브라우저에서 재현·캡처 |
| 원인 설명 | 왜/어떻게 그 오류가 나는지 메커니즘 설명 | — |
| 수정 | 수정 방향만 제시, 코드는 대신 고치지 않음 | 에디터에서 직접 코드 수정 |
| 반영 | git 명령어를 설명으로 제시 | 터미널에서 직접 `add`/`commit`/`push` 실행 |
| 검증 | 산출물(파일·스크린샷)을 다시 읽어 실제로 맞는지 확인 | 배포 사이트에서 결과 재확인 |
