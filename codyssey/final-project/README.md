## 1. 문제 상황

이제 막 스무 살이 된 사회 초년생에게 첫 아르바이트는 준비 없이 시작된다. 특히 카페·음식점처럼
음식을 다루는 매장은 음료 레시피, 조리 순서, 위생 기준, 마감 청소 절차처럼 **순서대로 정확히
해내야 하는 일**이 많다. 그런데 교육은 대부분 첫 출근 당일, 바쁜 영업 시간 사이에 구두로 한 번
이뤄진다. 매장이 주는 자료도 PDF 파일이나 인쇄된 레시피표, 단체 채팅방 공지처럼 "읽고 외우는"
형태라서 직접 해보기 전까지는 기억에 남지 않는다.

그 결과 신입 알바생은 레시피를 잘못 만들어 재료를 버리거나, 마감 절차를 빠뜨려 다음 날 문제를
만들거나, 위생 기준을 놓쳐 지적받는다. 이 실수는 본인에게는 위축감과 조기 퇴사로, 매장에는
재료 손실과 재교육 비용으로 돌아온다. 연습해보고 싶어도 집에는 재료도 기계도 없다.

게다가 이들에게는 **따로 공부할 시간이 없다.** 신입 알바생 상당수는 학생이거나 다른 일을
병행하고 있어, 책상 앞에 앉아 레시피를 외울 시간을 따로 내기 어렵다. 더구나 레시피와 절차는
한 번에 오래 본다고 외워지는 종류가 아니라 **짧게 여러 번 반복해야 몸에 남는** 종류다.
그런데 매장이 준 PDF는 그렇게 쓸 수 없다. 파일을 찾아 열고, 스크롤해서 위치를 찾고, 어디까지
봤는지 다시 기억해내야 한다. 화장실에 있는 2분, 버스 안의 10분, 마감 전 쉬는 시간 5분처럼
**하루에 흩어져 있는 짧은 틈새 시간에는 손도 댈 수 없는 형태**다. 결국 자료는 받았지만
열어보지 않게 되고, 첫 출근 날 아무것도 모르는 채로 서 있게 된다.

이 문제를 게임으로 풀려는 시도는 이미 있었다. 맥도날드는 신입 직원 교육용으로 닌텐도 DS 게임
**eCrew Development Program(eCDP)** 을 만들어, 화면 상단에 조리 절차와 진행도를 띄우고
하단에서 직접 감자를 튀기고 기름을 빼고 포장하는 과정을 따라 하게 했다. 패티 굽기부터 화장실
청소까지 다룰 만큼 현실 고증이 철저했다. 다만 이 프로그램은 맥도날드 내부 한정 비매품이라
정식 발매되지 않았고, 개인 매장이나 일반 알바생은 지금도 쓸 수 없다.
즉 **"알바 전에 미리 연습해본다"는 방식은 효과가 이미 검증됐지만, 대기업 안에만 갇혀 있다.**

## 2. 문제 대상

**주 대상** — 식품업(카페·음식점·베이커리 등) 매장에 채용이 확정됐지만 아직 일이 손에 익지 않은
신입 아르바이트생. 특히 아르바이트 경험이 전혀 없는 10대 후반~20대 초반 사회 초년생.

이들이 공통으로 가진 조건:

| 조건 | 설명 |
|---|---|
| 자료는 있으나 안 외워짐 | 레시피·매뉴얼(PDF·사진·인쇄물)을 이미 받았지만, 읽기만 해서는 기억에 남지 않는다 |
| 연습할 환경이 없음 | 첫 출근 전에 혼자 해보고 싶어도 집에는 재료도 장비도 없다 |
| 공부 시간을 낼 수 없음 | 학업이나 다른 일과 병행해 따로 시간을 내기 어렵다 |
| 쓸 수 있는 건 틈새뿐 | 하루 중 가용 시간은 이동·대기처럼 **몇 분짜리 조각**이다 |
| 읽기와 수행의 간극 | 업무가 "지식"이 아니라 **순서와 손동작**이라 글로 읽은 것이 실제 수행으로 이어지지 않는다 |

**간접 수혜 대상** — 매장 점주·점장. 재교육에 드는 시간과 신입의 실수로 발생하는 재료 손실이 줄어든다.

## 3. 해결할 과제

### (1) 매장마다 다른 자료를 학습 콘텐츠로 바꾸는 것

알바생이 받은 레시피·매뉴얼 자료를 앱에 넣으면, AI 에이전트가 내용을 읽고 무엇을 연습해야
하는지 스스로 뽑아낸다. 매장마다 레시피와 마감 절차가 다르므로, 고정된 콘텐츠를 미리 만들어
두는 방식으로는 풀 수 없다.

### (2) 내용 유형에 맞는 연습 방식을 고르는 것

같은 자료 안에도 성격이 다른 정보가 섞여 있다. AI 에이전트가 유형을 판별해 각각에 맞는 방식으로
변환한다.

| 자료 내용 유형 | 예시 | 연습 방식 |
|---|---|---|
| 제조 절차 | 아메리카노·라떼 레시피, 조리 순서 | 순서 맞추기 |
| 점검 절차 | 마감 청소, 오픈 준비, 위생 점검 | 체크리스트 수행 |
| 암기 정보 | 메뉴 가격, 알레르기 유발 재료, 보관 기한 | 퀴즈(객관식·주관식) |

### (3) 틈새 시간에 한 손으로 학습할 수 있게 하는 것

이 앱의 핵심 강점은 **"언제든 꺼내 쓸 수 있다"** 는 점이다. 이를 위해 다음을 만족해야 한다.

- **학습 단위를 1~2분 안에 끝나게 자른다** — 레시피 하나, 마감 절차 한 구간처럼 한 입 크기로 쪼갠다
- **세로 화면·한 손 조작** — 걸으면서, 서서, 엄지만 써서 진행할 수 있어야 한다
- **열면 바로 시작** — 메뉴를 거치지 않고 지난번에 틀린 항목부터 즉시 이어서 한다
- **네트워크 없이 동작** — 지하철·엘리베이터처럼 신호가 끊기는 곳에서도 멈추지 않는다

### (4) 실수해도 안전한 환경에서 반복하게 하는 것

실제 매장에서의 실수는 재료 손실로 이어지지만, 시뮬레이터 안에서는 몇 번을 틀려도 비용이 0이다.
틀렸을 때 "왜 틀렸는지"와 "올바른 순서"를 즉시 알려주어 실수가 학습으로 이어지게 한다.

### (5) 내 매장에 맞게 고칠 수 있게 하는 것

AI가 만든 문항이 실제 매장 기준과 다를 수 있다(시럽 펌프 횟수, 마감 순서 등).
사용자가 문항 내용과 정답을 직접 수정할 수 있어야 한다.

### (6) 약한 부분을 알려주는 것

어떤 절차에서 반복해서 틀리는지 기록해, 첫 출근 전에 무엇을 더 봐야 하는지 알려준다.

## 4. 핵심 설계

### 전체 흐름

```
[알바생] 매장에서 받은 자료(PDF·사진) 업로드
            │
            ▼
[AI 에이전트] 내용 분석 → 3개 유형 중 하나로 분류 → 문항 데이터(JSON) 생성   ← AI 호출은 여기 한 번뿐
            │
            ▼
[앱] 유형에 맞는 위젯 템플릿에 문항을 넣어 화면 구성
            │
            ▼
[알바생] 틈새 시간에 1~2분씩 한 손으로 학습 (오프라인 동작)
            │
            ▼
[앱] 오답 기록 → 다음에 열면 틀린 것부터 이어서
```

### 설계 원칙 — "AI는 기능을 만들지 않고, 내용만 채운다"

기획 초안에서는 *AI가 추천한 방법대로 기능을 구현해 앱 안에 시스템을 만들어준다*고 구상했다.
그러나 이를 문자 그대로 구현하면 **AI가 코드를 생성해 실행하는 구조**가 되어, 프로젝트 기간 내
비현실적이고 임의 코드 실행이라는 보안 문제도 따라온다.

그래서 다음과 같이 재정의했다.

| 구분 | 원안 | 확정안 |
|---|---|---|
| AI가 하는 일 | 기능(코드)을 생성 | **템플릿 선택 + 문항 JSON 생성** |
| 위젯 | AI가 즉석에서 생성 | **3종을 미리 구현해 둠** (순서 맞추기 / 체크리스트 / 퀴즈) |
| AI 호출 시점 | 학습할 때마다 | **자료 업로드 시 1회** |

사용자 눈에는 "AI가 내 자료를 보고 학습 기능을 만들어줬다"로 **동일하게 보인다.**
게다가 AI 호출이 업로드 시점 한 번뿐이므로 **학습 중에는 저장된 데이터만 읽어 오프라인으로
동작**하며, 이것이 (3)번 틈새 학습 요구와 정확히 맞아떨어진다.

### 접근성에서 파생된 설계 제약

| 제약 | 이유 |
|---|---|
| 순서 맞추기는 드래그가 아니라 **탭 선택** | 한 손으로 걸으면서 드래그앤드롭은 불가능 |
| 문항 하나 끝날 때마다 **진행 상태 자동 저장** | 아무 때나 끊기는 상황을 전제로 함 |
| **자유 배치·크기 조절 기능 제외** | 화장실에서 2분 쓰려는 사람이 위젯을 배치하지 않는다 |
| **손님 응대 롤플레이 제외** | 한 세션 5~10분 + 긴 텍스트 입력 → "걸으면서 한 손으로"가 성립하지 않음 |

> 매뉴얼에 응대 스크립트가 포함돼 있으면 "암기 정보 → 퀴즈"로 자연스럽게 커버된다.
> 별도의 대화 시뮬레이션 기능은 두지 않는다.

## 5. 기능 구현 가능성 평가

| 기능 | 판정 | 근거 / 조건 |
|---|---|---|
| ① 자료 입력(PDF·사진) | ✅ 가능 | `pdfplumber`로 텍스트 추출. 인쇄물 사진은 별도 OCR 없이 AI API에 이미지를 직접 첨부해 처리 |
| ② AI 분석·유형 분류 | ✅ 가능 | structured output(JSON 스키마 고정)으로 분류. 유형→방식 매핑을 **규칙으로 먼저 고정**하고 AI에는 판별만 맡길 것 |
| ③ 학습 기능 생성 | ⚠️ **설계 변경 후 가능** | 코드 생성 방식 ✗ → **템플릿 + JSON 주입** 방식 ○ (4장 참고) |
| ④ 문항 세부 수정 | ✅ 가능 | 난이도 낮고 실용성 높음 |
| ⑤ 오프라인 학습 | ✅ 가능 | AI 호출이 업로드 시 1회뿐이므로 구조상 자연스럽게 성립 |
| ⑥ 자유 배치·크기 조절 | ❌ 제외 | 구현은 가능하나 틈새 학습 컨셉과 충돌 |

**업종을 식품업으로 좁힌 것이 기술적으로 결정적이다.** 자료 유형이 3가지로 한정되므로 AI 분류가
안정적으로 동작한다. 업종 제한이 없었다면 유형이 발산해 AI 판단을 신뢰하기 어려웠을 것이다.

### 추가 검토 사항

- **자료 저작권·영업비밀** — 매장 레시피는 영업비밀일 수 있다. 업로드 자료는 **개인 계정 안에만
  비공개 저장**하고 외부 공유나 공개 학습 데이터 활용은 하지 않는다.
- **AI 분류 신뢰성** — "왜 이 방식이 효과적인가"의 근거가 없으면 AI가 그럴듯한 말만 하는 기능이
  된다. 유형→방식 매핑표를 문서로 고정해 판단 근거를 남긴다.

## 6. MVP 범위

| 우선순위 | 기능 |
|---|---|
| 1 | 자료 업로드(PDF·이미지) → 텍스트 추출 |
| 2 | AI 분류 → 3개 유형으로 문항 JSON 생성 |
| 3 | **순서 맞추기 위젯(탭 방식)** + **체크리스트 위젯** ← 핵심 |
| 4 | 퀴즈 위젯 |
| 5 | 문항 세부 수정 |
| 6 | 오답 기록·약점 표시 + 진행 상태 자동 저장 |

**제외**: 손님 응대 롤플레이, 자유 배치·크기 조절
**보너스**: 학습 진행률 대시보드, 틈새 학습 알림

## 7. 레퍼런스

**맥도날드 eCrew Development Program (eCDP)** — 닌텐도 DS, 신입 직원 교육용 비매품

- 출처 영상: [맥도날드에서 게임을 만든 적 있다고?](https://www.youtube.com/shorts/soKAgw4wyZs) (채널 게임동아, 52초)
- 확인한 화면 구성: 상단에 조리 절차(`手順`) 체크리스트와 `05/10` 진행도 카운터, 하단에서 실제 조작
- 확인한 게임 내용: 감자를 튀김기에 넣기 → 기름 빼기 → 종이 포장에 담기, 패티 굽기, 화장실 청소
- 정식 발매되지 않은 내부 한정판으로, 현재 이베이에서 200~300만 원대에 거래

**이 프로젝트가 참고한 점** — eCDP는 퀴즈가 아니라 **절차 수행 시뮬레이션**이었다. 신입 교육에서
중요한 것이 "지식"이 아니라 "순서"라는 점을 보여준다. 본 프로젝트도 순서 맞추기와 체크리스트를
핵심 위젯으로 삼았다.

**이 프로젝트가 다르게 가는 점** — eCDP는 맥도날드 한 회사의 고정된 절차만 담았고 전용 게임기가
필요했다. 본 프로젝트는 **매장마다 다른 자료를 AI가 읽어 콘텐츠를 만들고**, 전용 기기 없이
**휴대폰으로 틈새 시간에** 학습한다.
