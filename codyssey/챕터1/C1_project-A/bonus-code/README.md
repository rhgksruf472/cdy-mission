# 보너스 1 — 디자인 시안 → HTML/CSS 코드 변환 체험

> 과제 원문 §5 보너스 1: "완성된 디자인 시안 이미지를 V0, ChatGPT 등을 활용해 HTML/CSS 코드로 변환해본다."

## 무엇을 했나

`design/final/`의 완성 UI 이미지 3장(메인 / 목록 / 상세)을 **HTML/CSS 코드로 재현**하고, 화면 전환까지 클릭되게 만들어 브라우저에서 동작하는 프로토타입으로 변환했다.

- 결과 파일: [`index.html`](index.html) — 단일 파일(외부 의존성 0), 더블클릭으로 브라우저에서 바로 열림.
- **이미지를 `<img>`로 삽입한 게 아니라** 레이아웃·색상·컴포넌트(검색바·카테고리 원형 아이콘·카드 리스트·상태 태그·하단 내비·상세 메타 정보)를 전부 CSS로 다시 그린 것 — "코드로 변환"의 취지에 맞춤.

## 사용 도구 (명시)

| 항목 | 내용 |
|------|------|
| 변환 도구 | **Claude (Claude Code, 모델 Opus 4.8)** — 이미지 3장을 입력으로 넣어 HTML/CSS 코드 생성 |
| 왜 이 도구? | 원문이 "V0, ChatGPT **등**"으로 도구를 열어둠. Claude Code도 이미지→코드 변환이 가능한 생성형 AI 도구라 채택. 별도 가입/크레딧 없이 로컬에서 즉시 코드화·검증이 가능해 선택 |
| 입력 | `design/final/screen01-main-final.png`, `screen02-list-final.png`, `screen03-detail-final.png` |
| 출력 | `index.html` (HTML + 인라인 CSS + 화면 전환용 최소 JS) |

## 이미지 ↔ 코드 대응

| 원본 이미지 | 코드에서 재현한 요소 |
|-------------|----------------------|
| 화면1 메인 | 상단 검색바(돋보기+세이지 필터 버튼), 카테고리 4원형(Fiction/Non-Fiction/Academic/Kids&YA), "Featured Books" 헤딩, 도서 카드(표지+제목+저자·상태+Exchange 버튼), 하단 내비 4개(Home 활성) |
| 화면2 목록 | 필터 칩 3개(Genre/Region/Condition), 우측 상태 태그(Like New/Good/Acceptable) 붙은 카드 리스트, 하단 내비(Search 활성) |
| 화면3 상세 | 뒤로가기(←)+"Book Detail" 헤더, 도서 표지 카드(The Whispering Woods), 제목·저자·설명, 2×2 메타 그리드(Condition/Location/Genre/Year), Posted by 영역, "REQUEST EXCHANGE" 버튼 |

## 프로토타입 동작 (보너스 플러스 — 코드니까 클릭까지 붙임)

- 메인/목록의 **도서 카드 클릭 → 상세 화면**으로 전환
- 상세의 **← 버튼 → 메인**으로 복귀
- 하단 내비 **Home ↔ Search**로 메인/목록 전환
- 상세의 **REQUEST EXCHANGE** 클릭 시 토스트 알림

> 참고: 표지 그림은 AI 이미지의 삽화를 CSS 그라데이션으로 근사한 것이라 원본과 100% 동일하지 않다(코드 변환의 한계 = 학습 포인트). 레이아웃·색·정보 구조는 원본을 그대로 따랐다.

## 학습 포인트

1. **AI 이미지 → 코드 변환의 강점과 한계**: 레이아웃/색/텍스트/컴포넌트 구조는 코드로 거의 그대로 옮겨지지만, 일러스트(도서 표지 그림)는 코드로 픽셀 단위 재현이 어렵다 → 이미지 그대로 넣거나 별도 에셋으로 빼야 함.
2. **디자인 시안이 "실제 작동하는 것"으로 넘어가는 마지막 단계**를 체험 — 정적 이미지에는 없던 클릭 전환(hotspot과 같은 개념)을 코드에서는 몇 줄로 붙일 수 있음. Figma 프로토타입(산출물③)의 Hotspot과 같은 흐름을 코드로도 구현해 본 셈.
3. AI가 만든 코드도 **색상 값·간격·폰트 크기는 사람이 원본과 대조·보정**해야 시안과 일치한다.
