# 산출물③ — Figma 프로토타입 실행 가이드 (우리 3화면 전용)

> 과제 요구사항: (1) 생성 이미지를 배치해 화면 흐름을 구성한 **Figma 프로젝트 링크**, (2) 클릭 가능한 영역(**Hotspot**) 또는 화면 전환 흐름 표시.
> Figma 처음이어도 따라 할 수 있게 우리 이미지(`design/final/`) 기준으로 정리. 예상 소요 20~30분.

---

## 0. 준비물

- 배치할 이미지 3장: `design/final/screen01-main-final.png` · `screen02-list-final.png` · `screen03-detail-final.png`
- 이미지 크기: 768×1376px (≈9:16 모바일) — 3장 동일.

---

## 1. Figma 가입 & 파일 생성

1. figma.com 접속 → 무료(Starter) 플랜으로 가입(구글 계정 가능).
2. 좌측 상단 **`+` → Design file**(또는 "New design file") 클릭 → 빈 캔버스 생성.
3. 파일 이름을 `Project A - BookSwap Prototype`으로 변경(좌상단 파일명 더블클릭).

---

## 2. 프레임 3개 만들고 이미지 채우기

프레임(Frame) = 화면 한 장을 담는 캔버스.

1. 왼쪽 도구바에서 **Frame 도구(단축키 `F`)** 선택 → 우측 패널의 프리셋에서 **Phone → iPhone 계열**(예: iPhone 14 = 390×844) 아무거나 선택해 프레임 3개 생성. (우리 이미지가 9:16이라 세로 폰 프레임이면 OK. 비율만 맞으면 정확한 기종은 상관없음)
2. 3개 프레임 이름을 각각 `01-Main`, `02-List`, `03-Detail`로 변경(레이어 패널에서 더블클릭).
3. 각 이미지를 **드래그&드롭**으로 해당 프레임에 넣기:
   - `screen01-main-final.png` → `01-Main`
   - `screen02-list-final.png` → `02-List`
   - `screen03-detail-final.png` → `03-Detail`
4. 이미지가 프레임보다 크면, 이미지 선택 후 모서리를 드래그해 프레임에 꽉 차게 맞춤(비율 유지: 모서리 드래그). 프레임 크기를 이미지에 맞춰 조정해도 됨.

> ⚠️ 비율 불일치 주의: 이미지가 9:16이니 프레임도 세로 폰. 가로 프레임에 넣으면 잘림.

---

## 3. Hotspot 연결 (우리 화면 흐름 설계)

우상단 **Prototype** 탭으로 전환. 아래 5개 연결을 만든다. (연결법: 대상 영역 클릭 → 나타나는 **파란 `+` 핸들**을 드래그해 목적지 프레임에 놓기 → 상호작용 설정 팝업에서 `On tap` / `Navigate to` 확인)

| # | 출발 화면 | 클릭 영역(Hotspot) | → 도착 화면 | 의미 |
|---|-----------|--------------------|-------------|------|
| 1 | 01-Main | "Featured Books" 첫 도서 카드(Patterns of Infinity) | 03-Detail | 메인에서 책 선택 → 상세 |
| 2 | 03-Detail | 좌상단 **←(뒤로가기)** 화살표 | 01-Main | 상세 → 메인 복귀 |
| 3 | 01-Main | 하단 내비 **Search** 아이콘 | 02-List | 메인 → 목록(검색/필터) |
| 4 | 02-List | 아무 도서 카드(예: Patterns of Resonance) | 03-Detail | 목록에서 책 선택 → 상세 |
| 5 | 02-List | 하단 내비 **Home** 아이콘 | 01-Main | 목록 → 메인 복귀 |

- **클릭 영역 만드는 팁**: 이미지는 통짜 PNG라 특정 버튼만 클릭 영역으로 잡으려면, 그 위치에 **투명 사각형(Rectangle, 채우기 투명/투명도 0%)**을 하나 덮어 그리고 그 사각형을 hotspot 출발점으로 쓰면 정확하다. (예: 카드 영역, ← 버튼 영역, 하단 내비 아이콘 영역 위에 투명 박스)
- 최소 요구는 "클릭 가능 영역 또는 화면 전환 표시"이므로 **1·2번(메인→상세→뒤로)만 있어도 통과**. 3·4·5번은 완성도용.

---

## 4. 동작 테스트 & 공유 링크

1. 우상단 **Present(▶)** 버튼 → 미리보기 모드에서 실제로 카드·뒤로가기·내비를 클릭해 전환이 되는지 확인.
2. 우상단 **Share** → 권한을 **"Anyone with the link – can view"**로 변경 → **Copy link**.
3. 이 링크가 산출물③ 제출용 URL. → README "산출물③" 항목과 requirements-checklist에 붙여넣기.

> ⚠️ 공유 권한을 "can view"로 안 바꾸면 평가자가 링크를 열 수 없다(가장 흔한 실수).

---

## 5. 완료 후 나에게 알려줄 것

- Figma **Share 링크**(URL) → README·체크리스트에 반영하고 산출물③을 ✅로 갱신.
- (선택) Present 모드 스크린 녹화나 스크린샷을 주면 `design/`에 프로토타입 동작 캡처로 보관.

---

## 참고 — 왜 이 흐름인가 (평가 대비)

화면 전환에 **"돌아가는 연결(뒤로가기)"을 최소 1개 넣는 게 핵심**이다. 앞으로 가는 흐름(메인→상세)만 있으면 "화면 전환 흐름"이 한 방향뿐이라 부자연스럽다. 뒤로가기(2번)와 하단 내비 복귀(5번)를 넣어 **왕복 흐름**을 만들면 실제 앱처럼 자연스럽고, 과제의 "화면 간 이동 흐름 표시" 요구를 확실히 충족한다.
