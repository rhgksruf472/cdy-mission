# Project A — 팀 역할 분배 & 킥오프 플랜 (사전 준비용)

> 랜덤 팀 편성 전에, 첫 회의에서 바로 꺼내 쓸 역할 분배안. 4명 기준으로 짜고 5명/3명/2명 변형을 함께 담았다.
> 과제 3대 산출물: ①UI 디자인 이미지(3장+) ②작업 로그 문서(프롬프트 초안→수정→최종) ③Figma 프로토타입(Hotspot). 도구: Adobe Firefly(이미지 생성) + Figma(프로토타입).
> 예습 컨셉: **중고 책 교환 플랫폼** (메인 / 목록 / 상세 3화면 이상).

---

## 1. 왜 이렇게 나누는가 (분배의 원리)

이 과제는 **기획 → 이미지 생성 → 후가공 → 프로토타입**으로 이어지는 선형 파이프라인이다.
"화면 하나씩 각자 담당"으로 나누면 스타일이 화면마다 달라져 일관성이 깨진다(과제 목표 3번: 이미지 일관성 유지). 그래서 **파이프라인 단계별로** 나눠, 같은 프롬프트 베이스·같은 생성 도구를 전원이 공유하도록 한다.

---

## 2. 4명 기준 역할 분배 (표준안)

| 트랙 | 역할명 | 담당 산출물 | 핵심 업무 |
|------|--------|------------|-----------|
| **A** | 🎯 서비스 기획자 | (사전 작업 → 전 산출물 기반) | 서비스 컨셉·핵심 기능 확정, 화면 3개(메인/목록/상세) 역할 정의, 화면별 요구사항을 B에게 전달 |
| **B** | ✍️ 프롬프트·이미지 생성 담당 | ① UI 디자인 이미지 | 화면별 프롬프트 설계, 이미지 생성 AI 실행, **수정 이력(초안→수정→최종)** 기록 → 작업 로그 문서 초안 |
| **C** | 🎨 후가공·일관성 담당 | ① UI 디자인 이미지(완성도) | 텍스트 깨짐·부자연스러운 요소 수정(인페인팅/아웃페인팅/업스케일링), 화면 간 스타일 일관성 검수(시드·레퍼런스 이미지 활용), 비율(9:16 또는 16:9) 준수 확인 |
| **D** | 🧩 Figma·문서 PM | ③ Figma 프로토타입 | 이미지 배치, Hotspot/화면 전환 연결, 작업 로그 문서 취합·정리, 도구명·레퍼런스 출처 명시 확인(제약사항 대조) |

> **누가 뭘 맡든 "과제 목표 4가지"는 전원이 설명할 수 있어야 함**(동료 평가 대비): ①프롬프트 구성 요소가 결과물에 미치는 영향 ②AI 이미지 문제점 식별·수정 방법 ③이미지 일관성 유지 방법(시드 고정·레퍼런스) ④기획→생성→후가공→프로토타입 워크플로우.

## 3. 인원별 변형

### 👥 5명일 때 (+1 트랙 분리)
- **E — 보너스·QA 담당**: 보너스 1(코드 변환 체험 — V0/ChatGPT로 HTML/CSS 변환) 전담, 또는 요구사항 체크리스트 대조·리허설·발표 진행.
- 화면 수가 많아지면(4개 이상) B(이미지 생성)에 E를 페어로 붙이는 것도 좋음.

### 👥 3명일 때 (트랙 병합)
- **A(기획)** → B에 흡수(기획하면서 바로 프롬프트 작성).
- **B(프롬프트·생성)** 유지 — 핵심 산출물이라 단독.
- **C+D** → 후가공 + Figma·문서 묶어 1명.

### 👥 2명일 때 (미정 대비)
- **1명**: A+B(기획 + 프롬프트·생성) → "기획·생성 담당"
- **1명**: C+D(후가공 + Figma·문서) → "완성도·프로토타입 담당"

## 4. 킥오프 진행 순서 (첫 회의 30분 + 이후 흐름)

**이미지 생성 도구·화면 정의가 먼저 정해져야 뒤 단계가 안 막힌다.**

```
[0] 전원 (첫 회의 30분)
    - 서비스 컨셉 1개 확정 + 화면 3개(메인/목록/상세) 역할 합의
    - 이미지 생성 도구 확정(저작권 문제없는 툴, 이름 명시) + 비율(9:16/16:9) 통일
    - 역할 배정, 과제 목표 4개 함께 읽기
        ↓
[1] 병렬 착수
    - A: 화면별 핵심 기능·레이아웃 요구사항 문서화     ─┐
    - B: 프롬프트 초안 v1 작성(화면 3개 공통 스타일 베이스)─┤→ 공유
    - D: Figma 프로젝트 개설 + 화면 프레임 뼈대(3개)     ─┘
        ↓
[2] 생성 (B 주도)
    - B가 화면별로 이미지 생성 → 초안 결과 공유
        ↓
[3] 검수·수정
    - C가 텍스트 깨짐/부자연스러운 요소 확인 → 후가공 또는 B에게 재생성 요청(프롬프트 v2)
    - B가 수정 이력(초안→수정→최종, 변경 이유·결과 차이) 기록
    - C가 화면 간 스타일 일관성(시드 고정·레퍼런스 이미지 재사용) 검수
        ↓
[4] 마무리
    - D가 최종 이미지를 Figma에 배치 + Hotspot/화면 전환 연결
    - D가 작업 로그 문서 최종 정리(도구명·레퍼런스 출처 포함)
    - 보너스: 완성 이미지를 V0/ChatGPT로 HTML/CSS 변환 체험
    - (5명이면) E 리허설·체크리스트 대조
```

**핵심 병목 주의**: 이미지 생성 도구·화면 비율(9:16/16:9)이 [0]단계에서 확정돼야 B가 프롬프트를 일관되게 짤 수 있다 → **도구·비율 합의를 가장 먼저 끝낼 것.**

## 5. 각 요구사항 → 담당 매핑 (누락 방지용)

| 요구사항 | 주담당 | 검증 |
|----------|--------|------|
| 이미지 생성 AI 1개 이상 사용, 툴명 명시 | B | D |
| 화면 3개 이상(메인/목록/상세), 9:16 또는 16:9 준수 | B | C |
| 프롬프트 수정 과정(초안→수정→최종) + 이유·결과 차이 기록 | B | D(문서화) |
| 텍스트 깨짐·부자연스러운 요소 수정(후가공) | C | D |
| 이미지 일관성 유지(시드 고정·레퍼런스) | C | B |
| Figma 배치 + Hotspot/화면 전환 | D | 전원 |
| 레퍼런스 출처 기록, 캡처물 도용 금지 | D | 전원 |
| 보너스: 코드 변환 체험(V0/ChatGPT) | (5명이면 E, 아니면 D) | 전원 |

## 6. 내가(사전 준비자) 회의에서 리딩할 포인트

- "화면별로 각자 다른 툴/프롬프트로 따로 만들지 말고, **같은 프롬프트 베이스 + 같은 도구**로 통일하자" — 스타일 일관성이 과제 목표 3번이라 이 한마디가 감점을 막는다.
- 이미 준비해 둔 **화면 요구사항 정의·프롬프트 초안**을 공유하면 초반 30분을 아낀다.
- **이미지 생성 도구부터 확정** — 안 그러면 화면마다 스타일이 갈려 후가공(C)이 두 배로 힘들다.
