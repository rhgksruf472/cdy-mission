# Project A — 4개 트랙 예습 브리핑 (전 트랙 대비용)

> 랜덤 팀에서 어느 역할이 걸려도 바로 리딩할 수 있도록, 4개 트랙을 각각 예습한다.
> 각 트랙: **목표 → 이것만 알면 됨 → 실습 스텝 → 자주 막히는 지점 → 회의 리딩 한마디**.
> 예습 컨셉: 중고 책 교환 플랫폼(메인/목록/상세). 도구: Adobe Firefly(이미지 생성) + Figma(문서화 및 프로토타입).

---

# 🎯 트랙 A — 서비스 기획자

### 목표
화면 3개(메인/목록/상세)의 핵심 기능과 역할을 정의해 B가 프롬프트를 짤 수 있는 형태로 문서화한다.

### 이것만 알면 됨 (핵심 개념)
1. **화면 역할 구분**: 메인(진입·탐색) / 목록(카테고리·필터·리스트) / 상세(개별 아이템 정보·액션 버튼) — 원문이 예시로 요구하는 최소 구성.
2. **핵심 기능 우선순위**: 모든 기능을 다 그리려 하지 말고, 화면마다 "가장 중요한 액션 1개"를 중심에 둬야 이미지 생성 AI가 레이아웃을 잘 잡는다.
3. **비율 결정**: 모바일(9:16) vs 데스크탑(16:9) 중 하나로 전체 화면을 통일해야 함(원문 요구사항).

### 실습 스텝 (중고 책 교환 플랫폼 기준)
1. 메인 화면: 서비스 로고/검색창 + 추천 도서 카드 리스트(홈 피드).
2. 목록 화면: 카테고리 필터(장르/지역) + 도서 리스트(썸네일+제목+상태).
3. 상세 화면: 도서 표지 이미지 + 상태/설명 + "교환 신청" 버튼.
4. 각 화면의 "핵심 기능 1개 + 보조 요소 2~3개"를 표로 정리 → B에게 전달.

### 자주 막히는 지점
- **기능을 너무 많이 욱여넣음** → 이미지 생성 AI는 요소가 많을수록 레이아웃이 무너짐. 화면당 핵심 요소 3~5개로 제한.
- **화면 간 네비게이션 미정의** → D가 Figma에서 Hotspot을 연결할 때 "어느 버튼이 어느 화면으로" 흐름이 없으면 막힘. 미리 화살표로 표시.

### 회의 리딩 한마디
> "화면마다 핵심 기능 1개씩 딱 정해서 전달할게요. 요소가 많으면 AI가 레이아웃을 못 잡으니 최소한으로 가요."

# ✍️ 트랙 B — 프롬프트·이미지 생성 담당

### 목표
화면별 UI 이미지를 생성하고, **수정 과정(초안→수정→최종)과 변경 이유·결과 차이**를 기록한다. (산출물 ①·②)

### 이것만 알면 됨 (프롬프트 설계 3원칙)
UI 이미지 프롬프트는 아래 요소를 명시해야 결과가 흔들리지 않는다.
| 축 | 내용 | 예시 |
|----|------|------|
| 스타일 | 톤앤매너·디자인 무드 | "미니멀, 파스텔톤, flat design" |
| 레이아웃 | 화면 구조·배치 | "상단 검색바, 카드형 리스트, 하단 네비게이션 바" |
| 색상 | 메인/보조 컬러 | "메인 컬러 베이지·브라운, 포인트 그린" |
| 비율/용도 | 플랫폼·해상도 | "모바일 UI, 9:16, Figma 스타일, high fidelity" |
| 금지 규칙 | 텍스트 깨짐 방지 | "실제 읽을 수 있는 간단한 라벨만, 과도한 텍스트 지양" |

- **"예쁜 앱 UI"(X) → "Mobile app UI, book exchange, minimal pastel style, card list layout, bottom nav bar, 9:16"(O)**: 모호한 지시는 실패한다.
- **일관성 유지**: 화면 3개를 만들 때 스타일 문구를 동일하게 재사용하거나, 도구가 지원하면 시드 고정/레퍼런스 이미지 업로드를 활용한다(과제 목표 3번).

### 실습 스텝
1. 화면 공통 스타일 베이스 문장 하나를 먼저 확정(예: "미니멀 파스텔 book exchange 앱 UI").
2. 화면별로 레이아웃만 바꿔 3개 프롬프트 작성(메인/목록/상세) → 초안 v1.
3. 실제 생성 → 결과 확인(레이아웃 무너짐, 텍스트 깨짐 등) → **수정 이력 기록**: (1)이전 프롬프트 (2)문제 원인 추정 (3)수정 프롬프트 (4)수정 후 결과 (5)학습 포인트.
4. 화면 3개가 스타일적으로 통일될 때까지 반복.

### 자주 막히는 지점
- **화면마다 스타일이 다르게 나옴** → 공통 스타일 문구를 프롬프트 앞부분에 고정하고 레이아웃 설명만 바꿀 것.
- **텍스트가 외계어처럼 깨짐** → 이미지 생성 AI의 고질적 한계. "no readable long text" 또는 짧은 라벨만 요청 + 후가공(C)에서 수정 전제로 진행.
- **수정 이력을 지어내면 안 됨** → 반드시 실제 생성 결과(원본 이미지 파일 보존)를 근거로 기록. (평가 핵심)

### 회의 리딩 한마디
> "공통 스타일 문장 하나로 화면 3개를 통일해서 만들게요. 텍스트 깨진 부분은 후가공에서 고치는 걸로 역할 나눠요."

# 🎨 트랙 C — 후가공·일관성 담당

### 목표
AI가 생성한 이미지 속 뭉개진 글자·부자연스러운 요소를 수정하고, 화면 간 스타일 일관성과 비율 준수를 검수한다. (산출물 ① 완성도)

### 이것만 알면 됨
- **인페인팅(Inpainting)**: 이미지 일부 영역만 다시 그리기 — 깨진 텍스트/버튼 영역 재생성에 사용.
- **아웃페인팅(Outpainting)**: 이미지 바깥으로 캔버스를 확장 — 비율이 안 맞을 때 화면을 늘리는 데 사용.
- **업스케일링(Upscaling)**: 해상도를 높여 선명하게 — 제출 전 화질 보정에 사용.
- 위 세 기능은 원문에 "필요시" 활용 가능한 선택 수단 — 없으면 텍스트 영역을 도형/실제 텍스트로 덮는 수동 편집(Figma에서도 가능)으로 대체 가능.

### 실습 스텝
1. B가 생성한 이미지 3장을 받아 텍스트 깨짐·비율(9:16/16:9)·이상한 요소를 체크리스트로 검수.
2. 문제 있으면: (a) 같은 도구의 인페인팅/업스케일 기능으로 재수정, 또는 (b) Figma에서 깨진 텍스트 영역 위에 실제 텍스트 박스를 덮어 가리는 방식으로 후가공.
3. 화면 3개를 나란히 놓고 스타일(색상·톤·레이아웃 문법)이 통일됐는지 확인 — 어긋나면 B에게 재생성 요청.
4. 최종 PNG/JPG로 내보내기.

### 자주 막히는 지점
- **후가공 도구가 유료/제한적** → 도구가 인페인팅을 지원하지 않으면 Figma의 도형·텍스트 레이어로 깨진 부분을 가리는 대체 수단을 명시하고 사용 이유를 문서에 기록(제약사항: 도구명·이유 명시 요구).
- **"수정 없이 그대로 제출"은 감점** → 원문이 명시적으로 금지. 아주 사소한 깨짐이라도 최소 1곳은 수정 흔적을 남길 것.

### 회의 리딩 한마디
> "생성된 이미지 3장은 제가 검수해서 깨진 글자·비율 문제부터 잡을게요. 재생성이 필요하면 바로 프롬프트 담당에게 넘길게요."

# 🧩 트랙 D — Figma·문서 PM

### 목표
완성된 이미지를 Figma에 배치해 화면 흐름(Hotspot)을 만들고, 작업 로그 문서를 정리한다. (산출물 ②·③)

### 이것만 알면 됨 (Figma 처음이어도 괜찮음)
1. **프레임(Frame)** = 화면 하나를 담는 캔버스. 모바일이면 375×812(9:16 계열) 등 규격 프레임을 만들고 이미지를 채운다.
2. **Prototype 탭** = 화면 간 연결을 만드는 곳. 버튼 영역을 선택하고 다른 프레임으로 화살표를 드래그하면 Hotspot(클릭 가능 영역)이 생긴다.
3. **Present(▶) 버튼** = 만든 흐름을 실제로 클릭해보며 테스트하는 미리보기 모드.

### 실습 스텝 (처음 사용자용)
1. figma.com 가입(무료 플랜으로 충분) → **New design file** 생성.
2. 프레임 3개 생성(메인/목록/상세, 화면 비율에 맞는 사이즈 프리셋 선택) → 각 프레임에 완성 이미지를 드래그&드롭으로 채우기.
3. 상단 우측 **Prototype** 탭으로 전환.
4. 메인 화면에서 "도서 카드" 영역 클릭 → 파란 연결점을 드래그해 상세 화면으로 연결(Hotspot 1개).
5. 상세 화면에서 "뒤로가기"를 목록/메인으로 연결 → 최소 2~3개 흐름 완성.
6. Present(▶)로 실제 클릭해 흐름이 작동하는지 확인.
7. 우상단 **Share** → 링크 복사(보기 권한 "Anyone with the link")해서 제출용 URL 확보.

### 실습 스텝 (작업 로그 문서)
1. 표 형식으로 정리: 화면 | 프롬프트(초안/수정/최종) | 수정 이유 | 결과 차이.
2. 사용 도구명(이미지 생성 AI, 후가공 도구, Figma) 명시.
3. 레퍼런스 이미지를 참고했다면 출처 URL 기록(캡처 도용 아님을 명확히).

### 자주 막히는 지점
- **이미지 비율과 프레임 사이즈 불일치** → 프레임을 이미지 생성 시 정한 비율(9:16 또는 16:9)에 맞춰 만들어야 이미지가 잘리지 않음.
- **Hotspot 방향이 꼬임** → 원래 화면으로 돌아가는 연결(뒤로가기)도 최소 1개는 넣어야 "화면 전환 흐름"이 자연스러움.
- **공유 링크 권한 미설정** → Share에서 "Anyone with the link – can view"로 바꿔야 팀 외부(평가자)도 볼 수 있음.

### 회의 리딩 한마디
> "Figma는 제가 처음이라 프레임부터 차근차근 만들게요. 완성 이미지 넘겨주시면 바로 배치해서 Hotspot 연결할게요."

## 📌 전 트랙 공통 (평가 대비)
어느 트랙이든 **과제 목표 4가지**는 스스로 설명할 수 있어야 한다(동료 평가):
1. 텍스트 프롬프트의 구성 요소(스타일·레이아웃·색상)가 결과물에 미치는 영향
2. AI 생성 이미지의 문제점(텍스트 깨짐·부자연스러운 요소) 식별·수정 방법
3. AI 생성 이미지의 일관성 유지 방법(시드 고정·이미지 레퍼런스 등)
4. 기획 → 이미지 생성 → 후가공 → 프로토타입으로 이어지는 AI 협업 워크플로우
