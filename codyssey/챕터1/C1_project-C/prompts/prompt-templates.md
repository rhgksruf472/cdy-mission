# 플랫폼별 프롬프트 템플릿 문서

> 산출물 ③. 하나의 주제(`{{topic}}`)를 3개 플랫폼(인스타그램·블로그·X)에 맞는 텍스트로 변환하는 프롬프트 설계와 수정 과정(초안→수정→최종)을 기록한다.
> **실측 원칙**: 아래 "수정 과정 기록"의 실제 AI 출력은 Make 워크플로우를 돌린 뒤 raw 로그(`../content/raw-logs/`)로 채운다. 지금은 초안(v1)과 설계 근거까지 확정된 상태.

---

## 0. 프롬프트 설계 원리 (3가지 축)

플랫폼별 프롬프트는 아래 3가지를 반드시 다르게 지정한다. 이것이 "포맷을 고려한 프롬프트 설계"의 핵심이다.

| 축 | 인스타그램 | 블로그 | X (구 트위터) |
|----|-----------|--------|--------------|
| **분량(글자 수)** | 짧은 캡션 2~4문장 | 본문 500자 이상 | 280자 이내 |
| **구조** | 캡션 + 해시태그 10개 내외 | 제목 + 소제목(H2) 3개 이상 + 문단 | 한 덩어리 요약 + 해시태그 2~3개 |
| **톤앤매너** | 친근·감성·이모지 허용 | 정보 전달·신뢰감·설명형 | 임팩트·핵심만·속도감 |

**설계 근거**: LLM은 "짧게 써줘" 같은 모호한 지시에 약하다. → **글자 수를 숫자로 못 박고, 출력 구조를 명시하고, 금지 사항(예: 인스타에 소제목 금지)을 넣어야** 플랫폼 특성이 안정적으로 반영된다.

## 2. 플랫폼별 프롬프트 (초안 v1)

### 2-1. 인스타그램
```
[인스타그램 캡션 작성]
주제: {{topic}}
- 2~4문장의 짧고 친근한 캡션. 이모지 2~3개 자연스럽게 포함.
- 첫 문장은 스크롤을 멈추게 하는 후킹 문장.
- 캡션 끝에 관련 해시태그 10개 내외를 한 줄로. (한글/영문 혼용 가능)
- 소제목, 번호 목록, 긴 설명 금지.
출력 형식:
캡션: (본문)
해시태그: #... #... (10개 내외)
```

### 2-2. 블로그
```
[블로그 본문 작성]
주제: {{topic}}
- 제목·소제목을 제외한 본문 문단들의 합계가 공백 포함 500자 이상. (제목/소제목은 글자수에 넣지 말 것)
- 구조: 제목 1개 + 소제목(##) 3개 이상 + 각 소제목 아래 2~4문장.
- 톤: 정보 전달형, 신뢰감 있는 설명체. 이모지 없음.
- 마지막에 1문장 마무리(요약 또는 행동 유도).
출력 형식:
제목: (제목)
## 소제목1
(문단)
## 소제목2
(문단)
## 소제목3
(문단)
```

### 2-3. X (구 트위터)
```
[X 게시물 작성]
주제: {{topic}}
- 공백 포함 280자 이내(반드시 준수). 핵심만 임팩트 있게.
- 한 덩어리 문장 + 관련 해시태그 2~3개를 끝에.
- 이모지는 0~1개.
출력 형식: (게시물 텍스트 한 줄)
```

## 3. 수정 과정 기록 (초안 → 수정 → 최종)

> 구조: (1) 이전 프롬프트·결과 → (2) 원인 추정 → (3) 수정 프롬프트 → (4) 수정 후 결과 → (5) 학습 포인트
> **개인 예습 실측** — 주제 "2026년 직장인 AI 생산성 도구 트렌드"로 Claude Opus 4.8(2026-07-18)에서 v1 프롬프트 실행 → PowerShell로 글자수·해시태그 실측 → 위반 교정.
> 근거 로그: `../content/raw-logs/v1-test-raw.md`, `../content/raw-logs/v2-test-raw.md`

### 3-1. 인스타그램 — 수정 없음 (v1 통과)
- (1) v1 결과: 캡션 126자, 해시태그 10개 (`v1-test-raw.md`)
- (2) 판정: 규칙(짧은 캡션 + 해시태그 10개 내외) 실측 통과 → 억지 수정 없이 v1을 최종 채택.
- (5) 학습 포인트: 규칙을 숫자로 명시("이모지 2~3개", "해시태그 10개 내외")한 프롬프트는 1회차에 바로 통과했다. **모호한 지시를 숫자로 못 박는 설계가 재작업을 줄인다.**

### 3-2. 블로그 — v1 위반 → v2 수정 (실측 근거)
- (1) v1 결과: 본문만 세면 **439자**로 500자 미달 (`v1-test-raw.md`, PowerShell 측정)
- (2) 원인 추정: v1 프롬프트의 "공백 포함 500자 이상"을 LLM이 **제목·소제목까지 포함**해 500자로 해석 → 순수 본문이 부족.
- (3) 수정 프롬프트(v2): "**제목·소제목을 제외한 본문 문단들의 합계가 500자 이상**"으로 범위를 명확히 지정 + 각 문단을 2~4문장으로 늘리도록 지시.
- (4) v2 결과: 본문 **563자**, 소제목 3개 → 통과 (`v2-test-raw.md`)
- (5) 학습 포인트: **글자 수 하한(최소)은 LLM이 자주 놓친다.** "500자 이상"처럼 셀 대상이 모호하면 제목·소제목까지 포함해 채우니, "무엇을 세는지"를 프롬프트에 명시해야 한다.

### 3-3. X — 통과(품질 보강)
- (1) v1 결과: 120자 → 280자 이내 통과 (`v1-test-raw.md`)
- (2) 판정: 상한은 통과했으나 예산의 절반만 써 정보량이 빈약.
- (3) 수정: 구체 업무(회의록·이메일·자료조사)와 핵심 메시지를 추가해 136자로 보강(여전히 280 이내).
- (5) 학습 포인트: **글자 수 상한(X)은 오히려 여유 있게 통과하지만, 짧다고 좋은 게 아니다.** 상한형은 "핵심을 빠짐없이 담되 N자 이내"처럼 정보 밀도까지 요구해야 한다.

### 최종 반영 (프롬프트 개선)
위 학습을 위 2-2 블로그 프롬프트에 반영: `- 공백 포함 500자 이상` → `- 제목·소제목을 제외한 본문 문단 합계 500자 이상`.

## 4. 보너스: A/B 톤 변형 프롬프트

같은 주제·같은 플랫폼에서 톤만 바꾼 2버전을 만들기 위해, 위 프롬프트에 아래 한 줄만 교체해 삽입한다.

- **버전 A (친근형)**: `톤: 친구에게 말하듯 편하고 감성적으로. 반말/구어체 허용, 이모지 적극 사용.`
- **버전 B (전문형)**: `톤: 전문가가 설명하듯 신뢰감 있고 정제된 문체. 존댓말, 이모지 최소화, 근거 중심.`

→ 실제 생성물·글자수 실측은 `../bonus/ab-test-raw.md`, 결과 비교·결론은 `../bonus/ab-test-report.md`에 정리(개인 예습 실측, 2026-07-20 완료).

## 5. 대표 이미지 프롬프트 (이미지 생성 AI 연동)

> 산출물 ②의 "대표 이미지 1장 이상"용. Make의 **Google Gemini › Generate an Image** 모듈에서 사용. 주제 `2026년 직장인 AI 생산성 도구 트렌드`.
> **이미지 프롬프트 설계 4요소** = 주제 + 스타일 + 구도 + 용도/금지. (텍스트 프롬프트와 마찬가지로 "무엇을·어떻게·어떤 용도로"를 못 박아야 흔들리지 않는다.)

### 5-1. 설계 근거
- **글자 금지 필수**: 이미지 생성 AI는 글자를 자주 깨뜨린다 → `no text, no letters` 명시.
- **얼굴 디테일 회피**: 실제 인물 얼굴은 왜곡되기 쉬움 → 사람은 심볼릭·부분(손·뒷모습)으로, 또는 아이콘·개념 위주 구성.
- **SNS 썸네일 지향**: 중앙 구도 + 여백 넉넉 + 밝고 미니멀 → 어느 플랫폼에도 무난. 종횡비는 인스타 범용 **1:1(정사각)** 권장.

### 5-2. 최종 프롬프트 (영문 권장 — 이미지 모델은 영어 프롬프트가 더 안정적)
```
A clean, modern flat-illustration hero image about AI-powered workplace productivity in 2026.
Minimal office desk scene: a laptop showing a glowing AI assistant interface, with abstract
automation flow lines connecting document, email, and calendar icons into one smooth stream.
Bright and airy palette (soft blue, white, subtle purple accent), professional and optimistic mood.
Centered composition, generous negative space, social-media thumbnail style, square 1:1.
No text, no letters, no words, no logos.
```

### 5-3. 한글 프롬프트 (백업 — Gemini는 한국어도 처리)
```
2026년 직장인의 AI 생산성을 상징하는 깔끔하고 모던한 플랫 일러스트 대표 이미지.
미니멀한 사무 책상: 빛나는 AI 어시스턴트 화면의 노트북, 문서·이메일·일정 아이콘이 하나의
자동화 흐름선으로 이어지는 구성. 밝고 산뜻한 색감(연한 파랑·화이트·은은한 보라 포인트),
전문적이고 긍정적인 분위기. 중앙 구도에 여백 넉넉, SNS 썸네일 스타일, 정사각 1:1.
글자·문자·로고 없음(no text).
```

> ⚠️ **도구 스펙 확인 대기**: Make의 Gemini 이미지 모듈에서 ①모델 선택지 ②종횡비/사이즈 옵션 유무 ③출력 방식(이미지 URL vs 바이너리 — 노션 첨부 연결에 영향) ④1회 생성 장수를 UI에서 확인한 뒤, 위 프롬프트의 `square 1:1` 지정 위치(프롬프트 내부 vs 모듈 옵션)를 확정한다.
